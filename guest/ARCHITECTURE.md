# Guest helper architecture

This document specifies the guest-side userland of Gondolin: the four helper
binaries that run inside the micro-VM and talk to the host over virtio-serial.
It is the reference for every implementation of the helpers (the Zig code in
`src/`, and ports to other languages).  Anything observable by the host —
message formats, error codes, flow control, process semantics — is normative.
Implementation notes that are specific to the Zig code are marked as such.

## 1. Overview

| Binary           | virtio-serial port | Role |
|------------------|--------------------|------|
| `sandboxd`       | `virtio-port`      | PID 1 supervisor: runs commands, file transfer, clock sync, VFS status |
| `sandboxfs`      | `virtio-fs`        | FUSE daemon; forwards filesystem operations to the host VFS |
| `sandboxssh`     | `virtio-ssh`       | Multiplexes host TCP streams to guest loopback services (sshd) |
| `sandboxingress` | `virtio-ingress`   | Same forwarder, for the ingress gateway (guest HTTP services) |

Boot sequence (driven by the init script generated by
`host/src/alpine/init-scripts.ts`):

1. init mounts `/proc`, `/sys`, `/dev`, tmpfs dirs, brings up networking.
2. init starts `sandboxfs --mount <dir> --rpc-path <port> --binds-file /run/sandboxfs.binds`
   in the background and waits (≤ 30 s) for `fuse.sandboxfs` to appear in
   `/proc/mounts`.  It then bind-mounts every path listed in the binds file
   and writes either `/run/sandboxfs.ready` or `/run/sandboxfs.failed`
   (containing a human-readable reason).
3. init starts `sandboxssh` and `sandboxingress` in the background.
4. init `exec`s `sandboxd`, which therefore runs as **PID 1** and inherits the
   three helpers above (and every orphaned process) as children.

All helpers are single-threaded.  `sandboxd` and the TCP forwarders are
`poll(2)`-driven event loops over non-blocking file descriptors;
`sandboxfs` is a synchronous request/response loop.

## 2. Common runtime conventions

- **Static Linux binaries.**  Targets: `aarch64-linux` and `x86_64-linux`.
  *(Zig: no libc at all; system calls go through `src/shared/sys.zig`, which
  wraps `std.os.linux` with Zig error sets and retries `EINTR`.)*
- **Single-threaded.**  No locks, no thread pools.  Concurrency comes from
  non-blocking fds and `poll(2)`.
- **SIGPIPE is ignored** in every helper so that writes to closed pipes and
  sockets fail with `EPIPE` instead of killing the process.
- **Every fd is `O_CLOEXEC`.**  Spawned commands only inherit what is
  explicitly `dup2`ed onto fds 0–2.
- **Logging** goes to stderr (init points it at the serial console), one line
  per `write(2)`: `<level>(<scope>): <message>`.  Release builds log at
  `info` and above; per-message and per-exec logging is `debug` only (the
  serial console is slow).
- **Memory.**  All buffers are bounded by protocol limits (§8).  *(Zig:
  debug builds use the leak-checking `DebugAllocator`, release builds the
  `brk` size-class allocator; per-message data is decoded into an arena that
  is reset after each message.)*
- **Errors.**  Per-request failures are reported to the host and never take
  the helper down.  Allocation failure inside the event loop is fatal (for
  `sandboxd` that panics the guest kernel, which the host observes as VM
  exit).

## 3. Wire format

### 3.1 virtio-serial ports

Ports are opened by name: `/dev/virtio-ports/<name>` if present, otherwise
the `/dev/vport*` device whose `/sys/class/virtio-ports/<dev>/name` equals
`<name>`.  Helpers retry every 100 ms until the port exists (`sandboxfs`
gives up after 50 attempts, see §6.6).  Ports are opened `O_RDWR |
O_NONBLOCK`; `sandboxfs` switches back to blocking mode.

Host connection state (Linux `virtio_console` semantics):

- While the host end is **not connected**, `read(2)` returns 0 (EOF) and
  `poll(2)` reports `POLLHUP` permanently; writes block / return `EAGAIN`.
- Event-loop helpers therefore treat EOF or `POLLHUP` without `POLLIN` as
  *disconnected*: they stop polling the port (otherwise poll spins), discard
  any partially received frame, and probe the port every 100 ms with a
  zero-timeout `poll` for `POLLIN|POLLOUT`.  The port counts as reconnected
  as soon as `POLLHUP` is no longer reported.
- `sandboxd` keeps its queued output across a disconnect (it is delivered
  after reconnect) and keeps all exec sessions running.  The TCP forwarders
  drop all streams and queued output on disconnect (the host side of those
  streams is gone).

### 3.2 Framing

Every message is one frame:

```
+----------------------+---------------------+
| length: u32 big-end. | payload: length B   |
+----------------------+---------------------+
```

- `length` ≤ `max_frame_len` = 4 MiB (4 194 304).  Applies to both
  directions.  A zero-length payload is a valid (but meaningless) frame.
- An incoming frame with `length > max_frame_len` is **skipped**: its
  payload bytes are read and discarded so the stream stays in sync, and the
  event is logged.  No reply is sent.
- Outgoing frames are queued whole; a frame is never interleaved with
  another frame.

### 3.3 CBOR subset

Payloads are CBOR (RFC 8949) restricted to:

| Major type | Supported |
|---|---|
| 0, 1 integers | values representable as `i64` (others → decode error) |
| 2 byte string, 3 text string | definite length only |
| 4 array, 5 map | definite length only |
| 7 simple | `false` (0xf4), `true` (0xf5), `null` (0xf6) |
| everything else | floats, tags, `undefined`, indefinite lengths → decode error |

Decoding rules:

- Nesting depth ≤ 64; a single array/map backing store ≤ 8 MiB; a
  container that claims more elements than there are remaining input bytes
  (≥ 1 byte per array item, ≥ 2 per map entry) is rejected before allocating.
- Text strings are not UTF-8 validated.  Trailing bytes after the first item
  are ignored.
- Map lookups compare text keys; with duplicate keys the first wins;
  non-text keys and unknown keys are ignored.

Encoding rules (guest → host):

- Item heads use the shortest argument encoding.
- Maps are keyed by text strings; optional fields whose value is absent are
  **omitted** (not encoded as `null`).
- Raw data (`data` fields) is a **byte string**; everything else that is a
  string is a text string.

### 3.4 Message envelope

```
{ "v": 1, "t": <text>, "id": <uint32>, "p": <map> }
```

| Key | Meaning |
|---|---|
| `v` | protocol version; always 1 when sending, ignored when receiving |
| `t` | message type |
| `id` | correlation id: exec/file request id, stream id, fs request id; `0` for unsolicited messages |
| `p` | payload map, **required** (send `{}` for empty payloads) |

Payload parsing (host → guest): fields documented with a default may be
absent; a `null` value counts as absent for optional fields; integer fields
must be non-negative and fit the documented width, otherwise the payload is
invalid (`InvalidValue`); a wrongly typed field is `InvalidType`; a missing
required field is `MissingField`.

## 4. sandboxd: control protocol (`virtio-port`)

### 4.1 Message types

Host → guest:

| `t` | Payload fields (default) | Purpose |
|---|---|---|
| `exec_request` | `cmd` text; `argv` [text] (`[]`); `env` [text] (`[]`); `cwd` text (none); `stdin` bool (false); `pty` bool (false); `stdout_window` u32 (0); `stderr_window` u32 (0) | start a command |
| `stdin_data` | `data` bytes; `eof` bool (false) | stdin for exec `id` |
| `pty_resize` | `rows` u32; `cols` u32 | resize the pty of exec `id` |
| `exec_window` | `stdout` u32 (0); `stderr` u32 (0) | add output credit for exec `id` |
| `file_read_request` | `path` text; `cwd` text (none); `chunk_size` u32 (0) | stream a guest file to the host |
| `file_write_request` | `path` text; `cwd` text (none); `truncate` bool (true) | start an upload |
| `file_write_data` | `data` bytes; `eof` bool (false) | upload chunk for `id` |
| `file_delete_request` | `path` text; `cwd` text (none); `force` bool (false); `recursive` bool (false) | delete a path |
| `time_sync` | `unix_ms` u64 | set the guest wall clock |

Guest → host:

| `t` | Payload | When |
|---|---|---|
| `vfs_ready` | `{}` (id 0) | once at startup, VFS mounted |
| `vfs_error` | `message` text (id 0) | once at startup, VFS failed |
| `exec_output` | `stream` `"stdout"`/`"stderr"`; `data` bytes (1–8192 B) | child output |
| `stdin_window` | `stdin` u32 (> 0) | stdin credit grant |
| `exec_response` | `exit_code` i32; `signal` i32 (omitted unless killed by a signal) | exec finished; last message for that id |
| `file_read_data` | `data` bytes (1–`chunk_size` B) | file content |
| `file_read_done` | `{}` | end of file |
| `file_write_done` | `{}` | upload complete |
| `file_delete_done` | `{}` | delete complete |
| `time_sync_done` | `{}` | clock set |
| `error` | `code` text; `message` text | see §4.6 |

Messages for different ids may be interleaved arbitrarily in both
directions; the guest processes host messages strictly in order.

### 4.2 Startup

After opening the port `sandboxd` sends exactly one of:

- `vfs_error` if `/run/sandboxfs.failed` exists: the message is the file's
  content (at most 4096 bytes read) trimmed of spaces/CR/LF/TAB, or
  `"vfs mount not ready"` if that leaves it empty;
- `vfs_ready` otherwise.

If the marker file exists but cannot be read, nothing is sent (logged).

### 4.3 time_sync

`clock_settime(CLOCK_REALTIME, unix_ms)` then `time_sync_done`.  On failure:
`error{id, "time_sync_failed", "clock_settime failed"}`.  `unix_ms` >
`i64::MAX` → `error{id, "invalid_request", "invalid unix_ms"}` (unreachable
in practice because such integers fail CBOR decoding).

### 4.4 Exec

**Start.**  On `exec_request`:

1. If a session with the same `id` is still running → `error{id,
   "exec_failed", "failed to execute"}`.  (Ids may be reused once the
   previous session's `exec_response` was sent.)
2. Validate `env`: every entry must contain `=`; otherwise `exec_failed`.
3. Build `argv = [cmd] ++ argv` and `envp` = sandboxd's own environment
   with every entry whose `KEY=` prefix matches an override removed, followed
   by the overrides in request order (no overrides → inherited environment
   unchanged).
4. Spawn the child (§5.3).  Any failure before or during `fork` →
   `exec_failed`.  Failures *after* fork (chdir, exec) are reported by the
   child itself: `chdir` failure exits with status 127 silently; `exec`
   failure writes `exec failed\n` to the child's stderr (the pty in pty mode)
   and exits with status 127.

The command is resolved like `execvpe(3)`: if `cmd` contains `/` it is used
as is, otherwise each `PATH` entry (from the child's `envp`, default
`/bin:/usr/bin`; an empty entry means the current directory) is tried in
order; `ENOENT`/`ENOTDIR` continue the search, `EACCES` is remembered and
reported if nothing else succeeds, any other error stops the search.

**Modes.**

- *Pipe mode* (`pty` false): stdout and stderr are separate pipes.  stdin is
  a pipe if `stdin` is true, otherwise `/dev/null`.
- *PTY mode* (`pty` true): stdin/stdout/stderr are one pseudo terminal (no
  initial window size, kernel default termios).  All output is reported as
  `"stdout"`.  stdin is always enabled (regardless of `stdin`).

**Output flow control.**  Each output stream has a credit counter.  Initial
credit = `min(16 MiB, window)` where `window` is `stdout_window` /
`stderr_window`, or 256 KiB if absent or 0; that value is also the stream's
credit cap.  `exec_window` adds credit (`credit = min(cap, credit + n)`;
fields absent/0 add nothing).  A stream is read only while it has credit,
and each read is limited to `min(8192, credit)` bytes; every byte sent in
`exec_output` consumes credit.  While a stream has no credit the child
eventually blocks on a full pipe — this is the intended backpressure.
Additionally *no* output is read while the guest's outgoing queue exceeds
1 MiB (§5.4).

**Stdin flow control.**  Sessions with stdin get an initial
`stdin_window{stdin = 4 MiB}` right after spawning.  For each `stdin_data`:

1. `len(data) > 4 MiB` → `error{id, "stdin_chunk_too_large", "stdin chunk exceeds queue limit"}`.
2. `queued + len(data) > 4 MiB` → `error{id, "stdin_backpressure", "stdin queue full"}`.
3. `len(data) > inflight` (more than the host was granted) → `stdin_backpressure`.
4. Otherwise the chunk is queued, then `inflight -= len`, and it is written
   to the child as the fd becomes writable.  If queueing fails (out of
   memory) → `error{id, "exec_failed", "failed to queue exec input"}` and no
   credit is consumed.

Here `queued` counts host bytes not yet written to the child and `inflight`
counts credit granted but not yet used; the guest maintains
`queued + inflight ≤ 4 MiB`.  Every byte that leaves the queue — written to
the child, or discarded because stdin is closed — is returned to the host as
credit.  Returned credit is coalesced into at most one `stdin_window` per
session per event-loop iteration.  These stdin errors are advisory: the
session keeps running.  If a session has no stdin (pipe mode with `stdin`
false), any non-empty `stdin_data` fails with `stdin_backpressure` and empty
ones are ignored.

`eof`: after all previously queued data has been written,

- pipe mode: the stdin pipe is closed; later `stdin_data` is accepted
  (subject to the checks above) and discarded, with credit returned;
- pty mode: a single `0x04` (`^D`, VEOF) byte is written; stdin stays open
  and later data is still delivered.  The `^D` does not consume credit.

If writing stdin fails (e.g. `EPIPE` because the child closed its stdin),
stdin is closed and all queued data is discarded (credit returned).

**pty_resize** sets the terminal size (`TIOCSWINSZ`, values clamped to
65535); ignored in pipe mode.

**Completion.**  A session finishes when *both*

- the child process has been reaped, and
- every output stream reached EOF or was force-closed:
  - pipe mode: stdout and stderr returned EOF (a background process that
    keeps the pipes open delays completion until it exits or closes them);
  - pty mode: the master returned EOF/`EIO`, **or** after the child exited
    either 250 ms passed or 64 KiB more output was read, whichever comes
    first (background jobs may hold the pty slave open forever).

A hung-up stream with no credit is also treated as EOF if no bytes are left
to read (`FIONREAD == 0`).  On completion the guest sends `exec_response`
with `exit_code = WEXITSTATUS` for normal exits, or `exit_code = 128 + sig`
and `signal = sig` when the child was killed by signal `sig`, then forgets
the session.  Messages for that id afterwards get `unknown_id`.

The host cannot kill sessions through this protocol; it can only stop
reading (credit runs out) or close stdin.

### 4.5 File operations

Paths: `path` must be non-empty and contain no NUL.  Absolute paths are used
as is; relative paths require an absolute `cwd` and are resolved
lexically (`.`/`..` collapsed, symlinks not resolved).  Violations fail with
the error name `InvalidValue`.

**Read.**  `file_read_request` opens the file (`O_RDONLY`).  Effective chunk
size: `chunk_size`, or 64 KiB if absent/0, clamped to [1 KiB, 1 MiB].  The
file is then streamed as `file_read_data` frames (one `read(2)` per frame,
so frames may be shorter than the chunk size) followed by `file_read_done`.
Streaming is incremental: one chunk per active read per event-loop iteration
and only while the outgoing queue is below 1 MiB, so concurrent exec output
keeps flowing.  An open or read error sends `error{id, "file_read_failed",
<error name>}` (possibly after some data frames) and ends the read.

**Write.**  `file_write_request` opens/creates the file (`O_WRONLY |
O_CREAT`, plus `O_TRUNC` if `truncate`, mode 0666 before umask).  Each
following `file_write_data` with the same `id` is written completely
(blocking) in order; the frame with `eof` closes the file and produces
`file_write_done`.  Other messages may be interleaved with an upload.

- Open failure → `error{id, "file_write_failed", <error name>}`; the upload
  stays registered in a *discarding* state so its remaining data frames are
  silently dropped until `eof`.
- Write failure, or an invalid `file_write_data` payload → same error, the
  file is closed and the rest of the upload is discarded.
- `file_write_data` for an id without an upload →
  `error{0, "invalid_request", "unsupported request type"}`.
- A new `file_write_request` forgets every upload still in the discarding
  state, and replaces an active upload with the same id.

**Delete.**  Synchronous.

- `recursive` false: `unlink(path)`; a missing path is an error unless
  `force`.  Directories fail (`IsDir`).
- `recursive` true: a path that normalizes to `/` fails with
  `CannotDeleteRootDirectory`; unless `force`, the path must exist (`lstat`);
  then the tree is removed without following symlinks:
  1. `unlink(path)`; success or `ENOENT` → done; `EISDIR` → walk it.
  2. Walk: open directories with `openat(parent, name, O_RDONLY |
     O_DIRECTORY | O_NOFOLLOW)` and list them with `getdents64`.  Entries of
     type `DT_DIR` are descended into; every other entry (including
     `DT_UNKNOWN`) is `unlinkat(dir, name, 0)`ed, and `EISDIR` turns it into
     a descent.  An entry that vanished (`ENOENT`) is skipped; a directory
     entry that is no longer a directory when opened (`ENOTDIR`, or `ELOOP`
     for a symlink) is unlinked instead.
  3. An emptied directory is removed with `unlinkat(parent, name,
     AT_REMOVEDIR)` (`ENOENT` is fine; `ENOTEMPTY` means something was
     created meanwhile and the directory is scanned again), then the scan of
     the parent continues.
  The walk holds a constant number of fds (the Zig code keeps the names of
  the directories between the root and the current directory and re-opens
  the parent by walking those names down from the root, so depth is only
  limited by memory, not by fds or `PATH_MAX`).

Success → `file_delete_done`; failure → `error{id, "file_delete_failed",
<error name>}`.

**Error names.**  The `message` of `file_*_failed` errors is a name from the
Zig standard library's error vocabulary (the host's tests match
`FileNotFound`).  The mapping is exact and pinned by the unit test

| `time_sync_failed` | id | `clock_settime failed` | §4.3 |
| `exec_failed` | id | `failed to execute` | §4.4 start failure |
| `exec_failed` | id | `failed to queue exec input` | out of memory queueing stdin |
| `unknown_id` | id | `request id not found` | exec input for a finished/unknown session |

## 5. sandboxd: internals

### 5.1 Process setup

1. Ignore `SIGPIPE`.  Make sure fds 0–2 are open (open `/dev/null` for any
   that is closed) so that pipes never land on them.
2. Open `virtio-port` (non-blocking), retrying every 100 ms.
3. Block `SIGCHLD` and create a non-blocking, close-on-exec `signalfd` for
   it.  The original signal mask is kept for children.
4. Queue the VFS status message (§4.2) and enter the event loop.

### 5.2 Event loop

One iteration:

```
fds = []
if port connected: fds += port (POLLIN, plus POLLOUT if outbox non-empty)
fds += sigchld signalfd (POLLIN)
for each session: fds += session fds (see below)
timeout = 0    if a file read is pending and outbox < high-water
        = min(time to next pty drain deadline, 100 ms if port disconnected)
        = -1   otherwise
poll(fds, timeout)
for each ready fd, in order:
    port:     flush outbox; read once (≤ 64 KiB), then handle every complete frame
    signalfd: drain it; reap with waitpid(-1, WNOHANG) until none left;
              for a pid that belongs to a session record its status;
              other pids are orphans and are just reaped
    session:  read output / write stdin (below)
if port disconnected: probe for reconnect
if outbox < high-water: send one chunk for every active file read
for each session (reverse order): enforce pty deadline, send coalesced
    stdin_window, and if finished send exec_response and destroy it
flush outbox (opportunistic, non-blocking)
```

Session poll entries:

- stdout / stderr: registered with `POLLIN` when the stream has credit and
  the outbox is below the high-water mark; registered with no events (to
  learn about `POLLHUP`) while it has not hung up yet; not registered at all
  once it hung up and may not be read (`POLLHUP` is level-triggered and
  would spin).
- stdin: `POLLOUT` while data is queued.

When an output stream reports readiness and may be read, one `read(2)` of
`min(8192, credit)` bytes is done: `> 0` → `exec_output`; `0`, or `EIO` on a
pty master → EOF.  If it hung up but may not be read, it is closed when
`FIONREAD` reports 0 bytes.

### 5.3 Spawning (exact steps)

Everything the child needs (argv, envp, cwd as NUL-terminated strings) is
prepared before `fork`; between `fork` and `exec` the child only makes
system calls.

Pipe mode: create stdout, stderr (and stdin if enabled) pipes, all
blocking and close-on-exec.  Child:

1. `SIGPIPE` → `SIG_DFL`; restore the original signal mask (unblocks
   `SIGCHLD`).  Other inherited dispositions are left alone.
2. `dup2` stdin pipe read end (or a fresh `/dev/null` fd) → 0, stdout write
   end → 1, stderr write end → 2.
3. `chdir(cwd)` if given (failure: `_exit(127)`).
4. `execvpe`; on failure write `exec failed\n` to fd 2 and `_exit(127)`.

Parent: close the child ends; set the parent ends `O_NONBLOCK`.

PTY mode: open `/dev/ptmx` (`O_RDWR|O_NOCTTY|O_CLOEXEC`), unlock
(`TIOCSPTLCK` 0), open `/dev/pts/<TIOCGPTN>` likewise.  Child: signal reset
as above, `setsid()`, `ioctl(slave, TIOCSCTTY, 0)`, `dup2(slave → 0, 1, 2)`,
then steps 3–4.  Parent: close the slave; the master (`O_NONBLOCK`) is both
the output stream and the stdin fd.

The child keeps sandboxd's session and process group in pipe mode (no
`setsid`).

### 5.4 Backpressure and memory bounds

- One outgoing queue (`Outbox`) per port.  High-water mark: 1 MiB.  Above
  it no child output and no file data is read; incoming control messages are
  still processed (they produce only small replies), so the queue is a soft
  limit: high-water + one round of reads (≤ 8 KiB per stream, ≤ chunk size
  per file read) + small replies.
- Per session: queued stdin ≤ 4 MiB; output is never buffered beyond one
  8 KiB read.
- Incoming frames ≤ 4 MiB; the reassembly buffer holds at most one frame
  plus one 64 KiB read.
- The queue's sent prefix is reclaimed once it exceeds 64 KiB and half the
  buffer, so memory is proportional to unsent data.

### 5.5 Invariants

- `exec_response` is the last message for an exec id; it is only sent after
  all output of that session was sent.
- Exec output is never dropped; it is only delayed by credit/backpressure.
- `queued + inflight ≤ 4 MiB` per session (stdin).
- Every child is reaped (sandboxd is PID 1), including orphans.
- Pty drain deadlines use `CLOCK_MONOTONIC`, so `time_sync` clock jumps do
  not affect them.
- A blocking operation in the loop is limited to regular-file I/O of one
  chunk (file read/write) and synchronous deletes.  Reading a FIFO or a
  device node via `file_read_request` can block the loop; the host must not
  do that.

## 6. sandboxfs: FUSE ⇄ filesystem RPC (`virtio-fs`)

### 6.1 Arguments and startup

`sandboxfs [--mount DIR] [--rpc-path PATH] [--binds-file PATH]`
(defaults `/data`, `/dev/virtio-ports/virtio-fs`, none; unknown arguments
are ignored).

1. Open `/dev/fuse` (`O_RDWR`).
2. Open the RPC port: up to 50 attempts, 100 ms apart, each trying `PATH`
   and then a scan for a port named `basename(PATH)`.  If that fails,
   continue in **stub mode** (§6.5).
3. With `--binds-file` and an RPC port: call `mounts`; on success write each
   bind path followed by `\n` to the file (`O_CREAT|O_TRUNC`, mode 0644).
   Every entry must be a text string starting with `/` without `\n` or NUL,
   otherwise nothing is written.  If the host reports an error, no file is
   created (init then falls back to the `sandboxfs.bind=` kernel argument).
   This happens before mounting so the file is complete when the mount
   appears.
4. `mount("sandboxfs", DIR, "fuse.sandboxfs", MS_NOSUID|MS_NODEV,
   "fd=<fd>,rootmode=40000,user_id=0,group_id=0,default_permissions")`.
5. Serve requests until the filesystem is unmounted (`ENODEV` on the FUSE
   fd → exit 0).

### 6.2 RPC protocol

Strictly synchronous on a blocking port: write one request frame, read one
response frame.

```
request:  { v: 1, t: "fs_request",  id, p: { op: <text>, req: { <fields> } } }
response: { v: 1, t: "fs_response", id, p: { op: <text>, err: <int>, res?: <map|null>, message?: <text> } }
```

- `id` starts at 1 and increments (wrapping from 2³²−1 to 1).
- The response must have `t = "fs_response"`, the same `id`, and the same
  `op`; otherwise the request fails with `EIO`.
- `err` is an errno (sign ignored; 0 = success; values ≥ 4096 → `EIO`).
- All request fields are unsigned integers unless noted.

### 6.3 Operation mapping

| FUSE opcode | RPC op and `req` fields | `res` fields used | Reply |
|---|---|---|---|
| `INIT` | — | — | see §6.4 |
| `LOOKUP` | `lookup` {`parent_ino`, `name` text} | `entry` | `fuse_entry_out` |
| `GETATTR` | `getattr` {`ino`} | `attr`, `attr_ttl_ms`? | `fuse_attr_out` |
| `SETATTR` | if `FATTR_MODE`: `chmod` {`ino`, `mode` & 07777} (host `ENOSYS` is ignored); if `FATTR_SIZE`: `truncate` {`ino`, `size`}; then `getattr` {`ino`} | as GETATTR | `fuse_attr_out`; other attributes are accepted and ignored |
| `READLINK` | `readlink` {`ino`} | `target` text | target bytes |
| `SYMLINK` | `symlink` {`parent_ino`, `name` text, `target` text} | `entry` | `fuse_entry_out` |
| `MKDIR` | `mkdir` {`parent_ino`, `name` text, `mode`} | `entry` | `fuse_entry_out` |
| `UNLINK` / `RMDIR` | `unlink` / `rmdir` {`parent_ino`, `name` text} | — | empty |
| `RENAME` | `rename` {`old_parent_ino`, `old_name` text, `new_parent_ino`, `new_name` text, `flags` = 0} | — | empty |
| `RENAME2` | same with the request flags; flags ≠ 0 → `EOPNOTSUPP` without RPC | — | empty |
| `LINK` | `link` {`old_ino`, `new_parent_ino`, `new_name` text} | `entry` | `fuse_entry_out` |
| `OPEN` | `open` {`ino`, `flags`} | `fh`, `open_flags`? | `fuse_open_out` |
| `OPENDIR` | — | — | `fuse_open_out{fh = nodeid}` |
| `READDIR` | `readdir` {`ino`, `offset`, `max_entries` = max(1, size / 256)} | `entries` [{`ino`, `name` text, `type`?, `offset`?}] | packed `fuse_dirent`s, see below |
| `READ` | `read` {`fh`, `offset`, `size` ≤ 60 KiB}, repeated | `data` bytes | concatenated data, see below |
| `WRITE` | `write` {`fh`, `offset`, `data` bytes (≤ min(size, 60 KiB))} | `size`? | `fuse_write_out` (default: bytes sent) |
| `CREATE` | `create` {`parent_ino`, `name` text, `mode`, `flags`} | `entry`, `fh`, `open_flags`? | `fuse_entry_out` + `fuse_open_out` |
| `RELEASE` | `release` {`fh`} | — | empty |
| `ACCESS` | `access` {`ino`, `mask`, `uid`, `gid`} (uid/gid of the caller) | — | empty |
| `FALLOCATE` | `fallocate` {`fh`, `offset`, `length`, `mode`} | — | empty |
| `COPY_FILE_RANGE` | `copy_file_range` {`fh_in`, `off_in`, `fh_out`, `off_out`, `len`, `flags`} | `size` | `fuse_write_out` |
| `STATFS` | `statfs` {`ino`}; host `ENOSYS` → defaults | `statfs` {`blocks`, `bfree`, `bavail`, `files`, `ffree`, `bsize`, `namelen`, `frsize`}? | `fuse_statfs_out` |
| `RELEASEDIR`, `FSYNC`, `FSYNCDIR`, `FLUSH`, `DESTROY` | — | — | empty |
| `FORGET`, `BATCH_FORGET`, `INTERRUPT` | — | — | no reply |
| `MKNOD`, `*XATTR` | — | — | `EOPNOTSUPP` |
| `IOCTL` | — | — | `ENOTTY` |
| anything else | — | — | `ENOSYS` (logged once per opcode) |

Host data mapping:

- `entry` = {`ino`, `attr`, `attr_ttl_ms`?, `entry_ttl_ms`?} →
  `fuse_entry_out{nodeid = ino, generation = 0, ttls}`.
- `attr` = {`ino`? (defaults to the entry/request ino), `size`? (0),
  `blocks`? (⌈size/512⌉), `atime_ms`?, `mtime_ms`?, `ctime_ms`? (0), `mode`?
  (0), `nlink`? (1), `uid`?, `gid`?, `rdev`? (0), `blksize`? (4096)}.
  Times are milliseconds since the epoch, split into seconds + nanoseconds.
- TTLs are milliseconds; default 1000 ms for attributes and entries.
- Optional numeric fields that are negative, out of range or mistyped count
  as absent; missing required fields (`entry`, `entry.ino`, `attr`, `fh` for
  OPEN/CREATE, `target`, `entries`, entry `ino`/`name`, `data`, `size` for
  COPY_FILE_RANGE, `statfs` when no error) → `EIO`.

READDIR: entries are packed as `fuse_dirent{ino, off = offset (0), namelen,
type (0)}` + name, padded to 8 bytes, **only while the record fits** in the
requested size; remaining entries are dropped (the kernel resumes from the
`off` of the last returned entry).  An empty reply means end of directory.

READ: the kernel's request is fulfilled with consecutive RPCs of at most
60 KiB until `size` bytes are collected or a reply is shorter than asked
(EOF).  A short reply for a non-EOF region would make the kernel assume EOF.

### 6.4 INIT

Reply `fuse_init_out` (64 bytes) with `major`, `minor` and `max_readahead`
echoed from the kernel, `flags = kernel_flags & (FUSE_ATOMIC_O_TRUNC |
FUSE_BIG_WRITES)`, `max_write = 61440` (60 KiB), `time_gran = 1`, all other
fields 0.  With `FUSE_ATOMIC_O_TRUNC` the kernel passes `O_TRUNC` in OPEN and
the host truncates through the handle.

### 6.5 Stub mode (no RPC port)

`LOOKUP` of `data` in the root returns a synthetic directory (ino 2, mode
040755, nlink 2); other lookups `ENOENT`.  `GETATTR` returns that directory
attr for any inode.  `STATFS` returns the defaults.  `INIT`, `OPENDIR` and
the empty-reply ops behave as usual; everything that needs the host returns
`ENOSYS`.

### 6.6 Errors and robustness

- Host errnos are passed through (`-errno` in `fuse_out_header`).
- Malformed responses, transport errors and short/invalid requests reply
  `EIO`; sandboxfs keeps serving.
- Reading the FUSE fd: `EINTR`, `EAGAIN` and `ENOENT` (request interrupted)
  are retried; `ENODEV` means unmounted (clean exit).
- Writing a reply: `ENOENT` (request was interrupted meanwhile) is ignored;
  `ENODEV` → exit.  Replies are written with one `writev`.
- The request buffer is 128 KiB (> `max_write` + headers).
- Defaults when the host lacks `statfs`: 16 777 216 blocks/files of 4096 B,
  `namelen` 255.

## 7. sandboxssh / sandboxingress: TCP forwarding

Both binaries run the same forwarder on their port (`virtio-ssh`,
`virtio-ingress`).  Streams are identified by the envelope `id` (chosen by
the host).

| `t` | Direction | Payload | Semantics |
|---|---|---|---|
| `tcp_open` | host → guest | `host` text, `port` u16 | connect to a loopback service |
| `tcp_opened` | guest → host | `ok` bool, `message` text (only when `ok` is false) | connect result |
| `tcp_data` | both | `data` bytes | stream data (guest → host: 1–8192 B per frame) |
| `tcp_eof` | host → guest | `{}` | host half-close |
| `tcp_close` | both | `{}` | stream closed |

- `tcp_open`: `host` must be `127.0.0.1` or `localhost`, otherwise
  `tcp_opened{ok: false, message: "only loopback allowed"}` (an existing
  stream with that id is left alone).  Otherwise an existing stream with that
  id is closed (sending `tcp_close`), a blocking `connect` to
  `127.0.0.1:port` is made and the socket is switched to non-blocking mode.
  Every `tcp_open` is answered: `tcp_opened{ok: true}`, or `ok: false` with
  the error name of whichever setup step failed (`ConnectionRefused`,
  `AccessDenied`, `NetworkUnreachable`, `ConnectionTimedOut`, `AddressInUse`,
  `WouldBlock`, `ProcessFdQuotaExceeded`, `SystemFdQuotaExceeded`,
  `SystemResources`, `OutOfMemory`, `Unexpected`); on failure the socket is
  closed and no stream is registered.
- `tcp_data` (host → guest) is appended to the stream's pending buffer and
  written as the socket becomes writable.  If pending + new data would
  exceed 256 KiB the stream is closed (guest sends `tcp_close`).  Data for
  unknown ids is ignored.
- `tcp_eof`: once the pending buffer is empty, `shutdown(SHUT_WR)`.
- `tcp_close` from the host: close the socket and echo `tcp_close` (only if
  the stream existed).
- Socket → host: sockets are polled for input only while the outbox holds
  less than 256 KiB.  One read of ≤ 8 KiB per wakeup; after `POLLHUP`/
  `POLLERR` the socket is drained until it would block or the outbox is full.
  Read returning 0 or failing, or a write failing (other than `EAGAIN`),
  closes the stream and sends `tcp_close`.  (There is no guest → host
  half-close.)  If `tcp_data` cannot be queued (out of memory) the stream is
  closed rather than losing bytes.
- Sockets with nothing to do (no pending data, input paused) are not polled.
- Invalid frames (bad CBOR, unknown `t`, missing `id`/`p`, bad payload) are
  logged and ignored.
- Port disconnect: all sockets are closed without notification, the outbox
  is cleared, and the forwarder waits for the host to reconnect (§3.1).

## 10. Porting notes

- Keep the architecture: single thread, `poll(2)`, one outbox per port,
  credit-gated reads, `signalfd` + `waitpid(-1, WNOHANG)` reaping.  Do not
  introduce a thread per exec session; ordering guarantees (§5.5) fall out of
  the single queue.
- Spawning needs `fork` + manual setup (pty, `setsid`, `TIOCSCTTY`, signal
  mask) — `posix_spawn` cannot make a controlling terminal portably.  Only
  async-signal-safe calls between `fork` and `exec`; prepare argv/envp before
  forking.  Rust: `libc`/`rustix` with `fork`, or `std::process::Command`
  with `pre_exec` for the pty/signal setup; keep the parent ends
  non-blocking.  C: musl, `openpty` or the `/dev/ptmx` sequence of §5.3.
- Remember the signal hygiene: ignore `SIGPIPE` in the helpers, reset it and
  restore the signal mask in children.
- Error names in `file_*_failed` / `tcp_opened` messages follow the tables
  above; `FileNotFound` is relied upon by the host.
- Recursive delete must not follow symlinks and must produce the error
  names of §4.5 (see the algorithm there).
- *(Zig-specific choices:* no libc and no `std.Io` runtime: all system
  calls, including file I/O and the recursive delete, go through
  `src/shared/sys.zig`, whose errno → error mappings are pinned by a unit
  test.  `std.Io` does not fit the event loops (readiness semantics such as
  `POLLHUP` handling and credit-gated reads are not expressible through it)
  and its vtable-based `Threaded` implementation would add ~100 KiB to
  sandboxd.  Protocol payloads are plain structs serialized by comptime
  reflection in `cbor.zig`.)
